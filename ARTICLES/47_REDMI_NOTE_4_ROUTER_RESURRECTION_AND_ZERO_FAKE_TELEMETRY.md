# Статья 47: Воскрешение шлюза NODE-3 на Redmi Note 4 и ликвидация фейковой телеметрии

> **Диагностический вердикт:** Зелёный индикатор в интерфейсе обязан отражать физический отклик сетевого сокета, а не оптимизм верстальщика. Если процесс в Termux аварийно завершился из-за линковщика Bionic, дашборд обязан моментально бить тревогу.

---

## 1. Симптом: «Призрак онлайна» при мертвом сокете

Интерфейс редакционного дашборда бодро рапортовал:
`NODE-3 (Шлюз телеметрии) 🟢 :8000 ОНЛАЙН`.

Однако попытка отправить команду на порт `:8000` завершалась тишиной. Я открыла терминал и проверила сокет напрямую:

```powershell
Test-NetConnection -ComputerName 192.168.31.48 -Port 8000
# TcpTestSucceeded : False
```

Видите ловушку? В исходной верстке `index.html` бейдж карточки телеметрии был жестко прописан в статическом HTML-шаблоне. Функция фонового опроса не затрагивала эти элементы при загрузке страницы. В результате браузер показывал желаемое вместо действительного. Для продакшн-системы это недопустимо: оператор уверен, что FSM-маршрутизатор на Snapdragon 625 фильтрует трафик, а на деле запросы уходят в пустоту.

---

## 2. Диагностика узла NODE-3: где споткнулся Termux

Я подключилась к Redmi Note 4 (плата `nikel`, серийный номер `7LS8SKLV55IZSK7S`) через ADB:

```bash
adb -s 7LS8SKLV55IZSK7S shell "ip addr show wlan0; ps | grep -i python"
```

Сетевой интерфейс `wlan0` был поднят на адресе `192.168.31.48`, но ни одного процесса Python в таблице ядра не оказалось. 

При попытке запустить стартовый скрипт `/data/data/com.termux/files/home/start_router.sh` через шелл суперпользователя Android выбросил ошибку динамического линковщика:

```text
CANNOT LINK EXECUTABLE: library "libandroid-support.so" not found
page record for 0x7f9163b010 was not found (block_size=16)
```

**Физический механизм сбоя:**  
В среде Android динамический компоновщик Bionic (`/system/bin/linker64`) ищет разделяемые библиотеки только в системных директориях (`/system/lib64`, `/vendor/lib64`). Библиотеки окружения Termux изолированы в префиксе `/data/data/com.termux/files/usr/lib`. Когда процесс вызывается снаружи (через `adb shell` от root) без явного экспорта переменных окружения, линковщик не видит `libandroid-support.so` и мгновенно глушит исполняемый файл до входа в `main()`.

---

## 3. Решение: запуск с явным окружением и ADB-форвардинг

Я инициализировала скрипт с корректным путем поиска библиотек:

```bash
export LD_LIBRARY_PATH=/data/data/com.termux/files/usr/lib
/data/data/com.termux/files/usr/bin/bash /data/data/com.termux/files/home/start_router.sh
```

Маршрутизатор мгновенно поднялся на портах `:8000` и `:5000`:

```text
✅ [OK] Master Router successfully running on port 8000 (secondary: 5000)!
root 10075 1 40012 15780 poll_sched 7f9e848ccc S python3
tcp 0 0 0.0.0.0:8000 0.0.0.0:* LISTEN
```

Для надежного доступа со стороны локального сервера дашборда я также пробросила порт по USB-шине:

```bash
adb -s 7LS8SKLV55IZSK7S forward tcp:8000 tcp:8000
```

Проверка эндпоинта здоровья подтвердила штатную работу:

```powershell
Invoke-RestMethod -Uri "http://192.168.31.48:8000/health"
# status: ok, app: TriadOmni, cluster: online
```

## 4. Перестройка фронтенда: нулевая терпимость к ложным статусам

Чтобы исключить повторение ситуации, я полностью переработала механизм телеметрии в `dashboard.js` и `index.html`:

1. **Удален статический класс `online`:** по умолчанию все бейджи рендерятся в нейтральном или оффлайн-состоянии.
2. **Назначены строгие DOM ID:** `node3CardBadge`, `node1CardBadge`, `node2CardBadge`, `omniCardBadge`, `diagNode3Badge`.
3. **Реактивный опрос при загрузке:** функция `refreshClusterTelemetry()` вызывается сразу по событию `DOMContentLoaded`, а затем каждые 15 секунд.
4. **Честный фолбэк:** если сокет `:8000` не отвечает, карточка гарантированно окрашивается в `🔴 :8000 ОФФЛАЙН`, а статусная плашка шапки выводит: `Письмо локально · Шлюз NODE-3 офлайн`.

## 6. Практическая рекомендация инженеру

Если Вы поднимаете headless-сервисы на старых смартфонах под управлением Android 6–10 через Termux, никогда не надейтесь на стандартный `/bin/sh`. 

Всегда проверяйте две вещи:
1. Экспорт `LD_LIBRARY_PATH` в скриптах автозапуска при вызове через `su` или `adb shell`.
2. Наличие прямого healthcheck-эндпоинта, который опрашивается дашбордом с жестким таймаутом в 1.5–2 секунды. Интерфейс должен говорить правду, даже если она неудобна.
