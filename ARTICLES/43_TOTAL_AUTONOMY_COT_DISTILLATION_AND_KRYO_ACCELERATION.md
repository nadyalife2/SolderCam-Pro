# Статья 43. Тотальная автономия: Дистилляция CoT-рассуждений, однослотовый турбо-кэш и разгон Snapdragon 865 без облаков

> **Аппаратная база:** Xiaomi Mi 10T 5G (`apollo`, Snapdragon 865, 8GB LPDDR5), OnePlus Nord N10 5G (`billie`, Snapdragon 690, 6GB LPDDR4X), Redmi Note 4 (`mido`, Snapdragon 625, DC-DC 4.18V).  
> **Инженерный девиз:** Облака могут упасть, отключить бесплатные квоты или заблокировать доступ по гео-IP. Локальный кластер обязан жить, думать и обучаться на 100% автономно.

## 1. Входная проблема: Куда утекают секунды и как выжать максимум из кремния?

Короче, предыстория такая. Я подняла на нашем флагманском узле **NODE-1 (Xiaomi Mi 10T 5G)** модель `Qwen3.5-9B-UD-Q3_K_XL` на 4.8 гигабайта. Вроде всё крутится: ядра Kryo 585 Gold/Prime молотят через `taskset -c 4,5,6,7`, контроллер заряда спит (`battery_charging_enabled=0`), перегрева нет. Но стоило мне заглянуть в системные логи `brain.log`, как у меня волосы встали дыбом:

```text
W srv load_model: cache_reuse is not supported by this context, it will be disabled
slot print_timing: prompt eval time = 34042.89 ms / 199 tokens (171.07 ms per token)
slot print_timing: eval time = 1774.20 ms / 6 tokens (295.70 ms per token, 3.38 tokens per second)
```

**Тридцать четыре секунды на осознание промпта из 200 токенов?!** Да вы издеваетесь! Так мы до пенсии ответа ждать будем. При этом сама генерация выдает честные 3.38 токена в секунду. 

И тут же встает второй вопрос: как заставить эту мобильную модель не просто отвечать по верхам, а **рассуждать как суровый инженер с паяльником** (выдавать честный `<think>` со сверкой даташитов, sysfs-нод и шин питания)? И самое главное — сделать это **без единой строчки зависимости от Google Colab, облачных API или платных серверов**.

Спокойно, садимся за консоль, открываем исходники `llama.cpp` и разбираем всё до винтика.

## 2. Раскопки в исходниках llama.cpp: Почему умер cache-reuse?

Смотри, какая штука. В документации `llama-server` черным по белому написано: флаг `--cache-reuse 256` умеет повторно использовать куски KV-кэша через механизм KV-shifting, превращая 34 секунды префилла в жалкие 40 миллисекунд. Но у нас сервер упрямо плевался ворнингом и выключал кэш.

Я полезла прямо в исходный код на телефоне через `grep` и раскопала функцию в `tools/server/server-context.cpp`:

```cpp
if (!llama_memory_can_shift(llama_get_memory(ctx_tgt))) {
    if (params_base.n_cache_reuse) {
        params_base.n_cache_reuse = 0;
        SRV_WRN("%s\n", "cache_reuse is not supported by this context, it will be disabled");
    }
}
```

А дальше по цепочке в `src/llama-model.cpp` и `src/llama-memory-recurrent.cpp`:
```cpp
// src/llama-memory-recurrent.cpp
bool llama_memory_recurrent::get_can_shift() const { 
    return false; 
}
```

**Вот они, главные грабли!**  
Архитектура `Qwen3.5-9B` — это гибридная модель. В ней помимо стандартных блоков внимания (Attention) встроены **рекуррентные слои (Recurrent / Linear Attention)**. Для обычных токенов с RoPE-позициями сдвиг кэша (KV-shifting) работает на ура. Но рекуррентные скрытые состояния накапливаются кумулятивно вдоль последовательности, их физически невозможно просто «сдвинуть» без пересчета всей рекуррентной цепочки!

Поэтому `llama.cpp` честно блокирует KV-shifting. Но! Это касается только *сдвига* произвольных кусков из середины. **Префиксный кэш с нулевого токена (Longest Common Prefix)** прекрасно работает, если не ломать его квантованием!

## 3. Грабли с многопоточностью слотов и калибровка под 1 слот

Следующий сюрприз ждал меня в распределении памяти:
```text
I srv load_model: initializing, n_slots = 4, n_ctx_slot = 4096, kv_unified = 'true'
```

Оказывается, по умолчанию `llama-server` поднимает **4 параллельных слота** под веб-сервер. Зачем нашему личному автономному ассистенту на телефоне 4 слота?! Они только фрагментируют память, жрут лишние гигабайты LPDDR5 и заставляют сервер сбрасывать контекст при малейшей конкуренции.

Я перевела сервер в монопольный режим **1 слота**:
- Указала `-np 1` (number of parallel slots = 1).
- Поставила `-ctk f16 -ctv f16` (полная точность KV-кэша без артефактов квантования q8_0).
- Подключила `-lcd "$HOME/lookup.cache"` (динамический кэш n-грамм).
- Добавила `--cache-reuse 256`.

Перезапустила сервер, загнала тестовый запрос и смотрю в лог:
```text
I slot select: id 0 | task -1 | selected slot by LCP similarity, f_sim_best = 0.500
I slot print_timing: prompt eval time = 5520.37 ms / 31 tokens (5.62 tokens per second)
I slot print_timing: eval time = 8684.89 ms / 30 tokens (3.34 tokens per second)
I slot print_timing: graphs reused = 42
I slot print_timing: graph reallocs = 0
```

Красота! Ноль реаллокаций памяти (`graph reallocs = 0`), 100% графов переиспользуются на лету, а повторный префикс системного промпта мгновенно подхватывается по совпадению LCP!

## 4. Развенчание мифа: OLED против IPS LCD на Mi 10T

Многие «гуру» на форумах советовали: *«Включи черную тему, сэкономишь 40% батареи на смартфоне!»*.  
Я решила не верить на слово и сняла телеметрию экрана через ADB:

```powershell
adb shell dumpsys display | grep -E "mMinLuminance|mScreenBrightness"
```

Экран Xiaomi Mi 10T 5G — это честная **IPS LCD матрица с частотой 144Hz AdaptiveSync** (`mMinLuminance=0.323`). У LCD-панелей светодиодная подсветка светит по всей площади матрицы независимо от того, черный пиксель на экране или белый! Экономия OLED на выключенных субпикселях здесь физически не работает.

Поэтому кибердек-дизайн с темной палитрой `#090d16` и неоновым цианом `#00ffcc` мы используем не ради мифических миллиампер, а ради **инженерной эстетики терминала, читаемости графиков и защиты глаз ночью**.

## 5. 100% Оффлайн Дистилляция: Генератор CoT (<think>) Датасетов

Теперь главное: как заставить локальную модель думать умнее, если у нас нет доступа к платным API и мы не хотим зависеть от облаков?

Я переписала скрипт `scripts/build_sft_dataset.py`, превратив его в автономную фабрику дистилляции знаний:
1. **Парсинг первоисточников:** Скрипт сканирует все 51 документ проекта (42 боевые статьи из `ARTICLES/` и системные доки из `cluster_docs/`).
2. **Анализ аппаратного контекста:** Для каждого фрагмента автоматически определяется целевой узел (`Mi 10T 865`, `Nord N10 690`, `Redmi Note 4 625`), критические ограничения (LPDDR5 16.5 GB/s, порог троттлинга 40°C, байпас батареи `battery_charging_enabled=0`).
3. **Синтез цепочки рассуждений (`<think>`):** До ответа модель учится структурировать мысль:
   - *Шаг 1:* Аппаратный контекст и процессор.
   - *Шаг 2:* Защитные проверки и sysfs-ограничения.
   - *Шаг 3:* Анализ задержки (нужен ли Fast-Path или глубокий расчет).
   - *Шаг 4:* Формулирование бескомпромиссного ответа в авторском женском голосе.
4. **Результат на диске:**
   - Базовый SFT датасет: `triad_omni_sft_dataset.jsonl` (918 КБ, 225,350 токенов).
   - Глубокий CoT датасет: `triad_omni_cot_dataset.jsonl` (1.23 МБ, **300,857 токенов** с блоками `<think>`).

```bash
python scripts/build_sft_dataset.py
# 📊 Сформировано 317 уникальных инженерных пар Инструкция-Ответ.
# 🧠 CoT Reasoning датасет: datasets/triad_omni_cot_dataset.jsonl (1234.0 КБ | ~300,857 токенов)
```

### Как это обучать без облаков?
- **Вариант 1 (Автономный ПК, GTX 1050 Ti):** 4-битная LoRA через Unsloth / bitsandbytes на локальной видеокарте. Датасет скармливается локально через `scripts/train_lora_local.py`.
- **Вариант 2 (Нативный llama-finetune):** В самом `llama.cpp` есть встроенный бинарник `llama-finetune`. Он умеет дообучать LoRA-адаптеры прямо на CPU и оперативной памяти ПК вообще без Python и PyTorch!
- **Вариант 3 (Опциональные облака):** Если интернет есть и хочется сэкономить время, датасет в один клик скачивается из веб-студии и скармливается в Kaggle (бесплатные 30 часов в неделю на двух Tesla T4) или Google Colab. Но если связи нет — мы ни секунды не стоим на месте.
