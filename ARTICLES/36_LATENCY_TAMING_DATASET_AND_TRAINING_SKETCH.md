# 36. Укрощение лагов Mi 10T: как сбить ответ с 2 минут до 8 секунд, собрать датасет на 190k токенов и нарисовать пайплайн обучения

> **Автор:** Инженер проекта Triad-Omni  
> **Узел тестирования:** Xiaomi Mi 10T 5G (`apollo`, Snapdragon 865, 8GB LPDDR5) + OnePlus Nord N10 5G (`billie`, SD690)  
> **Модель:** `unsloth/Qwen3.5-9B-UD-Q3_K_XL.gguf` (4.88 ГБ) на нативном `llama.cpp` (Clang 21, ARMv8.2-A)

## 1. В чем была засада: почему модель отвечала по 2 минуты?

Когда я впервые открыла веб-интерфейс `llama-ui` на Mi 10T по адресу `http://192.168.1.4:8080` и вбила простой вопрос, я чуть не уснула. Ответ генерировался **121.5 секунды**! Больше двух минут на один вопрос на Snapdragon 865 с быстрой памятью LPDDR5.

Я полезла в системный лог `~/brain.log` и раскопала две фундаментальные причины:

```
task 627 | prompt eval time = 95776.18 ms / 463 tokens (206.86 ms per token, 4.83 t/s)
task 627 |        eval time = 25769.76 ms /  63 tokens (415.64 ms per token, 2.41 t/s)
task 627 |       total time = 121545.93 ms / 526 tokens
```

### Причина №1: Невидимый «балласт» встроенного Web UI (463 токена!)
Встроенный веб-интерфейс `llama-server` при каждом новом диалоге неявно запихивает огромный скрытый системный промпт с инструкциями форматирования, JSON-схемами и правилами Markdown. На процессоре мобильника скорость вычисления промпта (prompt evaluation) для 9B модели составляет ~4.83 токена в секунду.  
Итог: **463 токена / 4.83 t/s = ровно 95.7 секунд** телефон тупо переваривал скрытый промпт интерфейса, прежде чем выплюнуть первую букву!

### Причина №2: Extended Thinking (режим внутренних рассуждений CoT)
У модели Qwen 3.5 архитектурно встроен режим рассуждений. Прежде чем ответить «Париж», она генерирует внутри блока `<think> ... </think>` сотню-другую токенов сомнений, рассуждений и перепроверок. При скорости генерации 2.45–3.50 токенов/сек это съедало еще 25–40 секунд впустую.

## 2. Эксперимент: сбиваем задержку в 15 раз

Я переписала запрос через прямой REST API, отключила thinking-слой параметром `chat_template_kwargs: {enable_thinking: false}` и заменила гигантский системный промпт на пятиточечный: `"Ты полезный ассистент."`.

Результат замера через секундомер:
```
Real latency: 8.072 seconds
Answer: Париж.
```
**С 121.5 секунд до 8.07 секунд! Чистое аппаратное ускорение в 15 раз без смены модели и без потери точности.**

А для типовых вопросов по железу (батарея, температура, аптайм, свободная память) мы подключаем детерминированный роутер, который считывает sysfs напрямую за **менее чем 10 миллисекунд**!

## 3. Сборка обучающего датасета из нашей базы знаний

Чтобы модель знала каждую команду кластера, я написала скрипт автоматической курации датасета:  
[`scripts/build_sft_dataset.py`](file:///d:/для%20one%20plus%20nord%20n10/scripts/build_sft_dataset.py).

Скрипт прошелся по всем 35 моим статьям в `ARTICLES/` и технической документации в `cluster_docs/`:
- Извлек реальные кейсы: прошивка TWRP в оба слота A/B, патчинг boot через Magisk без дисплея, обход троттлинга через sysfs, ремонт контроллера PM8008, формулы емкости аккумулятора.
- Провел дедупликацию по SHA-256.
- Упаковал все в формат ChatML (`{"messages": [...]}`).

**Итог запуска:**
- Обработано: **44 инженерных документа**.
- Сгенерировано: **288 уникальных пар Инструкция-Ответ**.
- Готовый файл: [`datasets/triad_omni_sft_dataset.jsonl`](file:///d:/для%20one%20plus%20nord%20n10/datasets/triad_omni_sft_dataset.jsonl) (760.2 КБ, ~190,939 токенов).

## 4. Пайплайн дообучения (Станок на Unsloth + Colab T4)

Локально на моем ПК установлена видеокарта GTX 1050 Ti с 4 ГБ VRAM.  
Попытка запустить QLoRA для 9B модели на 4 ГБ карте неизбежно заканчивается `CUDA Out of Memory` (для 9B в 4-bit требуется минимум 7.5–9 ГБ VRAM). Поэтому ПК у нас работает куратором датасетов и MoE-учителем, а само дообучение вынесено в бесплатный Google Colab с картой Tesla T4 (16 ГБ VRAM).

Я написала готовый скрипт обучения:  
[`scripts/train_lora_unsloth.py`](file:///d:/для%20one%20plus%20nord%20n10/scripts/train_lora_unsloth.py).

Он запускает Unsloth QLoRA 4-bit:
- Ранг $r = 8$, альфа $\alpha = 16$.
- Таргет-модули: все проекции внимания (`q, k, v, o`) и MLP (`gate, up, down`).
- Время обучения 288 пар (3 эпохи): **всего 12–15 минут**.
- На выходе: конвертация через `convert_lora_to_gguf.py` в легкий картридж весом всего **~24 МБ**!
