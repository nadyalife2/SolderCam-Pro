## Пункт 1. Проверка мгновенного переключения LoRA-адаптеров на Mi 10T

Выполните на ПК или Mi 10T:
```bash
# 1. Проверка видимости всех трех адаптеров
curl -s http://192.168.1.201:8080/lora-adapters | jq .

# 2. Переключение на домен Пайка (id 0 = 1.0, остальные = 0.0)
curl -s -X POST http://192.168.1.201:8080/lora-adapters \
  -d '[{"id":0,"scale":1.0},{"id":1,"scale":0.0},{"id":2,"scale":0.0}]'

# 3. Инвалидация слота контекста
curl -s -X POST http://192.168.1.201:8080/slots/0?action=erase
```

**Критерий успеха:**
- В логе `~/brain.log` отсутствуют ошибки тензоров и сообщения об OOM.
- Время ответа команды переключения — менее 15 миллисекунд.

## Пункт 4. Тест каскадной эскалации `/v1/escalate` и изоляция приватного реверса

Выполните тестовые запросы эскалации через шлюз Note 4:

### Тест 4.1. Общий домен (`esp32`):
```bash
curl -s -X POST http://192.168.1.203:8000/v1/escalate \
  -H "Content-Type: application/json" -H "X-Omni-Token: $OMNI_TOKEN" \
  -d '{"domain":"esp32","prompt":"Напиши функцию мигания LED","reply":"void setup() {}","error":"undefined reference to digitalWrite"}' | jq .
```
**Критерий:** ответ содержит `"source": "distill_flash"` и корректный C++ код. В файле `~/omni_hub/data/datasets/sft_esp32.jsonl` появилась новая запись.

### Тест 4.2. Приватный домен (`reva_android`):
```bash
curl -s -X POST http://192.168.1.203:8000/v1/escalate \
  -H "Content-Type: application/json" -H "X-Omni-Token: $OMNI_TOKEN" \
  -d '{"domain":"reva_android","prompt":"Разбери ARM64 инструкцию","reply":"mov x0, #1","error":"segfault"}' | jq .
```
**Критерий:** ответ содержит `"source": "distill_local"` (обработано на ПК `:8090`). **Запрос не покинул локальную сеть LAN** (проверено через монитор трафика роутера / `tcpdump`).

## Пункт 5. Безопасность и хранение секретов

Проверьте переменные окружения и права доступа:
```bash
# На всех узлах:
ls -la ~/omni_env.sh
# Ожидается: -rw------- (права 600)
```
**Критерии:**
- `DEEPSEEK_API_KEY` и `OMNI_TOKEN` заданы **только** через переменные окружения, ни один API-ключ не захардкожен в скриптах.
- Доступ к API шлюза без заголовка `X-Omni-Token` возвращает HTTP `401 Unauthorized`.
- Вход по паролю по SSH отключен (`PasswordAuthentication no` в `sshd_config`).

## Пункт 6. Аппаратная проверка питания и защиты от перенапряжения

1. **Замер напряжений под нагрузкой:**
   - Напряжение на контактах P+/P− платы Mi 10T в режиме покоя: **4.08–4.10 В**.
   - Напряжение в момент prefill (нагрузка 3.5 А): **не менее 3.98 В** (просадка < 100 мВ).
2. **Пульсации:** осциллограф на контактах батарейного шлейфа показывает пульсации < **30 мВ** (благодаря полимерному конденсатору 470–1000 мкФ и керамике).
3. **Crowbar-защита:** тестовое превышение напряжения на стенде (> 4.7 В) мгновенно пережигает плавкий предохранитель 4 А, спасая PMIC.
4. **Правило USB:** физический тумблер питания выключается ДО подключения USB-кабеля к ПК.

## Пункт 7. Автономность после выключения интерфейса Android (`stop zygote`)

На Mi 10T и Nord N10 выполните:
```bash
su -c "stop surfaceflinger && stop zygote"
```
Через 15 минут проверьте:
1. Пинг до смартфона: `ping 192.168.1.201` — потери пакетов 0%.
2. Проверка ядра: `su -c "cat /sys/power/wake_lock"` содержит имя `omni_brain` / `omni_reflex`.
3. Энергосбережение Wi-Fi: `iw dev wlan0 get power_save` показывает **off**.
4. В Веб-Дашборде Note 4 статус узлов — **ONLINE**, температура обновляется каждые 10 секунд.
